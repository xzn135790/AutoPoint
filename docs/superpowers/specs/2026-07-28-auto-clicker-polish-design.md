# 连点器执行反馈与悬浮交互优化设计

## 背景

当前项目已经具备方案管理、点击与滑动录制、无障碍手势执行、录制悬浮面板和方案运行气泡。本次优化聚焦五个问题：

1. 方案运行时看不到每一步的点击或滑动痕迹。
2. 录制悬浮面板不能按统一比例缩放，文字和控件也不随尺寸变化。
3. 方案运行气泡过长，需要改成圆形小按钮。
4. 每轮间隔只能使用固定值，需要支持正负随机偏移。
5. App 图标需要替换为与连点器业务无关的原创二次元女性头像。

本次采用最小侵入方案，沿用现有服务、引擎、数据模型和持久化结构，不重构整套悬浮系统。

## 目标与非目标

### 目标

- 执行每一步时显示实际随机坐标对应的淡色痕迹和步骤编号。
- 点击痕迹和滑动轨迹在约 0.8 秒内渐隐消失。
- 录制面板支持横向或纵向拖动触发的等比例缩放。
- 面板内文字、按钮、边距和间距随面板统一缩放。
- 方案运行控件改为头像式圆形按钮。
- 每轮间隔支持固定值加减均匀随机值。
- 旧方案数据继续正常读取。
- App 图标替换为原创黑发霓虹风格二次元女性头像。

### 非目标

- 不重构 `FloatingControlService` 的整体职责。
- 不修改无障碍手势的派发方式。
- 不改变步骤延时、持续时间和坐标随机偏差的现有语义。
- 不持久化录制面板缩放比例；服务重新打开时恢复默认尺寸。
- 不处理与本次需求无关的原有 warning 或其他问题。

## 现状与根因

`AutoClickEngine` 在派发手势前通过 `StepListener` 回传实际起点、终点和步骤编号，`FloatingControlService` 也已经具备 `ExecutionPreviewView` 绘制能力。

当前通过方案气泡运行时看不到轨迹的直接原因是：步骤回调检测到 `profileBubbleView` 存在后立即返回，导致 `showCurrentExecutionPreview(...)` 永远不会执行。现有预览视图也没有自动渐隐机制。

当前录制面板的窗口宽度和高度分别根据横向、纵向拖动距离计算，没有统一缩放因子；内部控件和文字仍使用 XML 中的固定尺寸，因此不属于整体等比例缩放。

## 总体架构

保持现有职责边界：

- `MainActivity`：编辑和保存方案运行配置。
- `ClickProfile`：保存固定轮次间隔和随机轮次间隔。
- `AutoClickEngine`：计算步骤实际坐标、执行步骤并等待下一轮。
- `AutoClickAccessibilityService`：派发系统手势并转发状态与步骤回调。
- `FloatingControlService`：管理录制面板、圆形运行按钮和执行轨迹层。

数据流如下：

1. 用户在主界面保存固定间隔与随机间隔。
2. `ClickProfileStore` 按现有 JSON 方式保存方案。
3. 运行方案时，`AutoClickEngine` 在每一步派发前计算实际随机坐标。
4. 步骤回调将实际坐标传给 `FloatingControlService`。
5. 服务显示不可触摸的轨迹层，同时无障碍服务继续派发真实手势。
6. 一轮完成且仍有下一轮时，引擎计算本轮随机间隔并进行可中断等待。

## 执行轨迹

### 显示规则

- 点击：显示半透明圆形标记和步骤编号。
- 滑动：显示半透明轨迹线、起点、终点和步骤编号。
- 轨迹使用引擎计算后的实际随机坐标，确保显示位置与真实手势一致。
- 轨迹层使用 `FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCHABLE`，不得拦截用户或目标 App 的触摸。
- 每次只保留当前步骤的轨迹，下一步到来时安全移除旧轨迹。
- 轨迹短暂保持后渐隐，总显示时间约 800ms。

### 生命周期

- 移除方案气泡存在时跳过预览的限制。
- 添加轨迹层失败时记录日志，但不得中断真实手势。
- 停止执行、执行完成、服务销毁或下一步到来时，取消旧动画并安全移除轨迹。
- 轨迹层添加后，将圆形运行按钮重新放到最上层。
- 动画结束回调只移除其对应的轨迹实例，避免旧回调误删新轨迹。

## 录制面板等比例缩放

### 尺寸与交互

- 基准尺寸保持为 `200dp × 260dp`。
- 在面板右下角提供明确的缩放手柄。
- 左上角作为缩放锚点，拖动过程中保持不动。
- 横向或纵向拖动均可触发缩放。
- 分别计算横向和纵向候选缩放值，使用偏离 `1.0` 更明显的一项作为统一缩放因子。
- 缩放因子限制为 `0.75～1.75`。
- 对应窗口尺寸约为：
  - 最小 `150dp × 195dp`
  - 最大 `350dp × 455dp`
- 缩放后限制窗口位置，确保主要操作区域仍位于屏幕有效范围内。

### 内容缩放

首次显示面板时记录以下基准数据：

- 文字字号。
- 控件宽高和最小宽高。
- 内边距。
- 外边距。
- 控件间距。

缩放过程中始终基于基准数据乘以统一缩放因子，不在上一次结果上继续累乘，避免尺寸漂移和舍入误差。状态文字、按钮、间距和缩放手柄均同步变化。

关闭悬浮服务后不保存缩放因子，再次打开时恢复默认尺寸。

## 头像式圆形运行按钮

### 外观

- 主按钮约为 `60dp × 60dp`。
- 主圆显示本次生成的二次元头像。
- 右下角显示独立的播放或停止状态角标。
- 待机时显示播放角标，执行中显示停止角标。

### 手势

- 轻点：待机时启动当前方案，执行中停止方案。
- 拖动超过 `4dp`：移动按钮，不触发轻点或长按操作。
- 长按约 `800ms`：停止执行、关闭按钮并停止悬浮服务。
- 一旦进入拖动状态，必须取消待执行的长按任务。
- 抬手或系统取消触摸时清理长按任务，避免延迟误触发。

### 状态同步

- 沿用现有无障碍状态回调更新执行状态。
- 方案为空或无障碍服务不可用时保持现有提示方式。
- 执行完成、被停止或失败时恢复播放角标。

## 每轮间隔随机值

### 数据模型

`ClickProfile` 新增非负字段：

```text
loopIntervalRandomMs
```

JSON 字段使用相同名称。读取旧 JSON 时缺失该字段则使用 `0`，从而保持旧方案行为不变。

以下路径必须同步支持新字段：

- 构造函数。
- JSON 读取与写入。
- 方案复制。
- Getter 与 Setter。
- 主界面绑定和保存。

### 主界面

在“每轮间隔”配置下新增输入项：

```text
间隔随机 ±（毫秒）
```

- 默认值为 `0`。
- 空值使用 `0`。
- 负数统一修正为 `0`。
- 保存后随方案切换、复制和重新打开正常恢复。

### 执行算法

每轮实际间隔按下式计算：

```text
actualIntervalMs = max(0, loopIntervalMs + randomOffset)
randomOffset ∈ [-loopIntervalRandomMs, +loopIntervalRandomMs]
```

- 范围内采用均匀随机分布。
- 对随机范围进行上限保护，避免乘法或边界计算溢出。
- 随机值为 `0` 时直接使用固定间隔。
- 只在当前轮结束且确实还有下一轮时等待。
- 等待必须继续响应暂停和停止。
- 每轮间隔不受方案倍速影响，保持现有时间语义。

## App 图标

### 图像方向

生成原创图像，要求如下：

- 成年黑发二次元女性。
- 酷飒气质。
- 紫蓝霓虹背景。
- 头像或肩部以上构图。
- 五官清晰，主体居中。
- 不包含文字、水印、手机、手指、点击器或自动化相关元素。

### Android 适配

- 生成高分辨率主图。
- 人物面部和关键轮廓置于自适应图标中央安全区域。
- 继续使用 Android 自适应图标结构。
- 在圆形、圆角矩形等常见桌面蒙版下不得裁切人物面部。
- 圆形运行按钮复用同一视觉资源，并通过圆形裁切显示。
- 播放和停止角标单独绘制，不写入原始头像图片。

## 错误处理

- 悬浮窗权限缺失时沿用现有授权提示，不创建轨迹或运行按钮。
- 轨迹层添加失败时记录异常并继续执行手势。
- 移除已不存在的悬浮层时安全忽略。
- 缩放过程中检查窗口和视图状态，服务销毁后不得继续更新布局。
- 随机间隔输入和 JSON 数据统一执行非负校验。
- 超大随机值进行上限保护，避免溢出。
- 图标资源必须通过 Android 资源编译验证。

## 测试与验收

### 自动测试

扩展 `ClickProfileTest`：

- 旧 JSON 缺少随机间隔时默认为 `0`。
- 新字段能够完成 JSON 往返。
- 方案复制保留随机间隔。
- 负值被修正为 `0`。

扩展 `AutoClickEngineTest`：

- 随机值为 `0` 时使用固定间隔。
- 实际间隔不低于固定值减随机值并截断到 `0`。
- 实际间隔不高于固定值加随机值。
- 停止操作能够中断轮次等待。

验证命令：

- `:app:testDebugUnitTest`
- `:app:assembleDebug`

构建时使用 Android Studio 自带 Java 21 JBR，不修改用户现有 Java 环境变量。若 Gradle 验证超过两分钟则停止继续等待，并报告已完成的验证结果。不处理原有 warning。

### 手动验收

- 从方案圆形按钮启动后，每一步均显示轨迹并在约 0.8 秒内渐隐。
- 点击和滑动显示的步骤编号正确。
- 轨迹位置与执行引擎最终随机坐标一致。
- 轨迹层不拦截触摸。
- 录制面板横向或纵向拖动均能等比例缩放。
- 面板文字、按钮、边距和间距同步缩放。
- 面板尺寸始终在限制范围内，关键控件不移出屏幕。
- 圆形头像按钮的轻点、拖动和长按互不冲突。
- 多轮执行的实际等待位于配置范围内。
- 旧方案无需迁移即可正常运行。
- 桌面常见图标蒙版不会裁掉人物面部。
